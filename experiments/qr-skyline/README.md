# URL City

把一个网页链接编码成标准 QR 矩阵，再把同一份可验证数据搭成一座 2.5D 像素城市。

## 30 秒体验路径

1. 输入 HTTP(S) 链接；省略协议时会自动补全 `https://`。
2. 点击“生成城市”，观察 CITY ID、矩阵规模、楼宇数和亮灯模块数随链接变化。
3. 点击城市或“验证二维码”，画面会还原为标准二维码。
4. 用扫码工具验证它仍然指向输入的规范化链接。

## 数据怎么变成城市

| 输入数据 | 城市表达 |
| --- | --- |
| 规范化 URL | QR 内容和城市种子 |
| QR 的一列 | 一栋楼 |
| 每列黑格密度 | 楼高 |
| 一个黑色模块 | 一盏亮窗 |
| URL 哈希 | 色彩、节奏、星空和 CITY ID |

城市和二维码不是两份互不相关的图。城市里的每一盏亮窗都有 QR 黑格来源，验证模式会把这些窗灯归位到原矩阵。

## 技术边界

- 原生 HTML、CSS、JavaScript 与 Canvas 2D；零构建、无服务端。
- 视觉是原创 2.5D 城市，不是 WebGPU 或真实 3D，也没有复用参考项目的代码和素材。
- QR 使用 M 级纠错、UTF-8 字节编码和四模块静区。
- 相同的规范化 URL 在当前算法版本中得到相同结构；CITY ID 只是短视觉指纹，不是密码学标识。
- 只接受 HTTP(S)。输入框限制 512 个键入字符；超过 QR 容量时会提示缩短链接。
- 高密度矩阵与 `prefers-reduced-motion` 会跳过 morph；页面不可见或父播放器隐藏时停止动画。

## 验证记录

2026-09-09 使用 Chromium `BarcodeDetector` 验证：

- 默认主页链接在 1200×750、390×844、320×700 独立视口可解码。
- 中文与 emoji 链接会先规范化为百分号编码，二维码解码结果与规范化 URL 完全一致。
- 180 个中文字符组成的测试路径会生成 153×153 矩阵；在 320×700 视口使用 1 CSS px 模块仍可解码。
- 主页 iframe 中的桌面视口与 320×700 父视口可解码。
- 同一规范化 URL 的城市数据相同，不同 URL 的城市数据不同。
- `javascript:` 与 `ftp:` 被拒绝，`example.com:8080/path` 与 `localhost:3000` 可正确补全协议。

浏览器自动解码不等于实体手机实扫；实体设备验证仍待单独完成。
